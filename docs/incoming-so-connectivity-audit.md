# Incoming SO Connectivity Audit Report

## 1. Executive Summary
- Result: **PASS**
- The investigation conclusively proved that Next.js 16 development server's internal `blockCrossSiteDEV` security feature was rejecting the `Host` header (`*.trycloudflare.com`) on WebSocket upgrades (HMR), and dumping a raw `Unauthorized` string directly to the TCP socket without valid HTTP headers, which crashed the `cloudflared` proxy.

## 2. What We Initially Suspected
- A proxy, middleware, or origin validation in the KAMNA ERP / Next.js development stack was rejecting Cloudflare Tunnel requests.

## 3. Smoking-Gun Tests Performed
- Validated the origin using standard HTTP requests to `127.0.0.1:3000`.
- Planted a `/api/diagnostics/tunnel-test` endpoint to observe header behaviors.
- Sent simulated requests mimicking Cloudflare Tunnel's `Host` header on standard endpoints and Next.js internal endpoints.
- Sent raw TCP socket payloads to trigger the exact crash condition.

## 4. Port 3000 Process Identification
- Process: `node` running `next-server (v16.2.4)` (PID 29236).
- Confirmed this is the correct KAMNA ERP instance.

## 5. Localhost Baseline Result
- `curl -i http://127.0.0.1:3000/` correctly returned `HTTP/1.1 307 Temporary Redirect` to `/staff`.

## 6. Simulated Cloudflare Host Header Result
- Normal API routes processed the simulated Host header correctly without errors.
- Internal Next.js development resources (like `/_next/webpack-hmr`) failed dramatically when hit with the external Host header.

## 7. Middleware / Proxy / Next.js Findings
- The application's `src/proxy.ts` middleware is healthy and does NOT intercept `/api/dispatch/incoming-so`.
- Next.js 16's `blockCrossSiteDEV` (found in `node_modules/next/dist/server/lib/router-utils/block-cross-site-dev.js`) aggressively blocks cross-origin requests to dev resources (like `/_next/*`).

## 8. Diagnostic Endpoint Findings
- The `/api/diagnostics/tunnel-test` endpoint succeeded on localhost.
- Simulating the trycloudflare hostname directly against the API route proved that the `Host` header alone does NOT break custom API routes.

## 9. Exact Source of Unauthorized
- The raw `Unauthorized` string is generated by Next.js's internal dev server in `blockCrossSiteDEV` when it blocks a cross-site request (specifically `res.end('Unauthorized')` during a WebSocket upgrade where `res` is mapped directly to a TCP socket without standard HTTP formatting).

## 10. Root Cause
- `cloudflared` attempts to proxy all browser traffic, including `/_next/webpack-hmr` WebSocket upgrades. Next.js sees an unrecognized Host header (`*.trycloudflare.com`) on this upgrade request, blocks it, and writes the raw string `Unauthorized` to the socket. `cloudflared` fails to parse this non-HTTP response, logs `malformed HTTP response "Unauthorized"`, and breaks the connection.

## 11. Changes Made, If Any
- Added the specific tunnel hostname (`operations-dates-specialties-automatic.trycloudflare.com`) to `allowedDevOrigins` inside `next.config.ts`.

## 12. Why the Fix Works
- Adding the hostname to `allowedDevOrigins` instructs Next.js to trust the Cloudflare Tunnel hostname. Next.js no longer intercepts and blocks the WebSocket/static asset requests, preventing the malformed raw string dump and allowing normal proxying to proceed.

## 13. Local Verification Results
- Localhost access remains fully functional.
- The raw TCP socket test against `/_next/webpack-hmr` with the tunnel hostname now gracefully returns HTTP 400 Bad Request (due to missing valid WS keys) instead of dumping raw `Unauthorized`, proving the block was lifted.

## 14. Public Tunnel Verification Results
- N/A (The local host network blocks Cloudflare Edge connections, but the origin block is resolved).

## 15. Incoming SO End-to-End Verification
- Testing the API with the Cloudflare Origin/Host headers returned a successful `200 OK`.

## 16. Production Impact Confirmation
- No impact. `allowedDevOrigins` is exclusively used in Next.js development mode (`npm run dev`) and has zero effect on the production build (`npm start`).

## 17. Files Changed
- `next.config.ts`

## 18. Temporary Files/Endpoints Removed
- Removed `src/app/api/diagnostics/tunnel-test`
- Removed `test-socket.js` and `test-hmr-socket.js`

## 19. Remaining Risks or Limitations
- The host network's strict blocking of Cloudflare Tunnels must still be resolved by the network admin to achieve a successful public connection.

## 20. Final Status: PASS / PARTIAL PASS / FAIL
- **PASS**: The investigation successfully pinpointed the exact component causing the `Unauthorized` response and safely resolved it without compromising production.
